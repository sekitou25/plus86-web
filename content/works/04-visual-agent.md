## 工作范围

我负责 Visual Agent 的整体设计与开发，覆盖知识模型、资料准备与审核、检索编译、不可变版本、任务编排、iOS Worker、视觉判定、Web 控制台、CLI / MCP 与报告链路。

Doku 是这套系统的首个业务场景：它将短剧观看、内容互动与 AI 辅助故事创作放在同一款产品中。播放器的连续状态、动态 Feed 和异步生成流程，让回归检查既依赖设备操作，也依赖对业务预期的理解。

## 从资料到正式知识

将业务概念、规则、页面、操作目标、断言、Fixture 与 Case 组织为可引用的知识节点。资料可以来自指定 Git Commit，也可以由网页上传并标准化为带行号文本。外部 Agent 或千问生成候选，候选保留 SourceRef、置信度、冲突与开放问题，经人审后进入统一编译。

检索使用 ID / alias、SQLite FTS5 和中文双字补召回，结合模块与平台过滤。当前没有引入 Embedding；先让规则关系、来源与精确引用可检查，再根据真实召回问题增加复杂度。

## 不可变知识版本

编译冻结知识、图片、用例和场景配置，基于内容摘要生成版本 ID，并保存 Manifest、数据库哈希与 Bundle。暂存目录、编译锁和原子替换共同控制发布过程。

任务显式绑定版本，并冻结模块、Case 和执行场景。版本不存在、内容被修改或强依赖缺失时，拒绝消费，不静默回退到可编辑工作区。版本固定的是测试依据；账号、网络与内容数据仍需要额外的环境治理。

## 设备执行与取证

以 DeviceDriver 隔离平台实现。Appium XCUITest / WDA 负责截图与触摸，simctl 负责 App 生命周期和 MP4 录屏；通过外部 App 产物或已安装 App 运行，不读取 Doku 业务源码。

32 条播放用例已接入执行，其中 31 条使用声明式 visual_scenario，点赞采用 visual_toggle。每条 Case 分别记录准备、动作、验证、清理和证据；任务聚合逐 Case 的结论、理由、测量值与 Artifact。

## 判定要匹配证据的证明范围

本地规则检查黑屏、区域变化、运动和点赞颜色等视觉事实。点赞场景先等待目标稳定出现，归一化初始状态，执行点击，再做连续帧验证，并尝试恢复可逆状态。

将 PASSED、FAILED、INCONCLUSIVE、INFRA_ERROR 与 NOT_RUN 分开。红色心形可以支持视觉激活断言，却不能单独证明服务端计数或跨页面持久化。证据不足时返回无法判定，避免把动作成功或画面变化直接等同于业务正确。

## 已验证范围

能力基线为 2026-08-19：知识版本包含 69 条稳定用例、207 个知识节点、454 条关系，以及 23 个已审核页面变体、53 个目标。69 条用例中，32 条已接入执行，其余 33 条为 planned、4 条为 blocked。

2026-08-11 的历史完整运行在 iPhone 16 Pro Simulator / iOS 18.2、Doku 1.2.0+2026080402 上执行：32 条实际运行，18 条通过、1 条失败、13 条无法判定，用时约 5 分 10 秒，保存 32 份录屏，基础设施错误和执行阶段模型调用均为 0。

该运行早于最新知识基线，当前数据库未归档该任务。以上数据来自已有记录，不能当作最新版本回归、全业务覆盖率或节省人力的证明。文档记录的 58 条 Python 测试与 Ruff 检查属于 2026-08-19 基线，本次作品整理没有重新运行 Visual Agent 测试。

## 下一阶段

优先补齐知识强引用、Fixture 的 prepare / verify / cleanup 生命周期、污染与故障检测，并建立固定版本的多轮回归和证据回放基线。之后按真实的无法判定案例引入独立语义 Verifier，再扩展创作场景与 Android Worker。

千问当前用于知识候选生成；自主规划、未知页面模型定位、执行阶段视觉大模型、统一 Fixture Runtime 与 Android 执行仍未完成。
