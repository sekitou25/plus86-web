## 这一篇要解决的问题
昨天的仓位到了今天为什么会变化？新信号出来后，是否每一点差额都要交易？这一章把价格漂移、交易缓冲、进出场阈值、财报过滤与执行时间放进同一个日常流程。
## 正文
**1 股数不变，仓位比例也会变化**
假设昨天策略净资产为 100,000 美元，持有 X 股票 100 股，每股 50 美元。X 市值为 5,000 美元，占净资产 5%。
今天 X 涨到 55 美元，其他资产价值不变，忽略费用。股票市值变成 5,500 美元，策略净资产变成 100,500 美元，实际仓位为：
```plain text
5,500 ÷ 100,500 ≈ 5.47%
```
所以，即使没有交易，仓位也会随价格和净资产变化。这叫仓位漂移。每天应先按新价格计算当前仓位，再与新目标比较。
**2 精确追踪目标会产生许多小额交易**
假设目标权重从 5.00% 改到 5.05%，策略净资产仍按 100,000 美元演示，目标金额只增加 50 美元。几十只股票每天都有这种微调，可能产生大量小订单。
每次交易可能支付佣金、买卖价差和滑点。滑点指实际成交价格与决策时参考价格之间的差异；较大订单还可能推动价格，形成市场冲击。这些成本可能超过小幅调仓带来的信号收益。
因此，目标与当前仓位有差额，只说明存在调整方向，还要判断差额是否值得交易。
**3 交易缓冲给目标周围留一个不交易区间**
这里必须区分函数版本。本章按本轮查到的公开 `rsims` 底层函数解释：`trade_buffer` 是权重区间的总宽度，两侧各取一半；超出区间后调回完整目标。目标为 0 时会清仓，小目标的区间在 0 处截断。[底层缓冲函数](https://raw.githubusercontent.com/Robot-Wealth/rsims/main/src/positionsFromNoTradeBufferMinComm.cpp)
例如，目标仓位为 +3%，`trade_buffer = 0.025`：
```plain text
总宽度 = 2.5 个百分点
两侧各留 = 1.25 个百分点
不交易区间 = 1.75% 至 4.25%
```

最后的股数还受整股取整、成本和保证金影响。1.25 个百分点以策略净资产为分母，不能读成目标金额的 1.25%，也没有止损线的含义。
本地 notebook 导出的 `deadband.rebalance_to` 写成了 `band_edge`，与上述公开函数的调到目标不同。Notebook 又没有固定依赖的 Git 提交，因此这套算例描述已查看的实现；复现保存结果时必须确认当时安装的函数版本，不能仅凭参数名称判断行为。
**4 缓冲还会影响是否建立小仓位**
假设目标为 +1%，总缓冲宽度仍是 2.5 个百分点。原来的下界为 −0.25%，函数将其截到 0，上界为 2.25%。
若当前仓位为 0，它已经位于这个区间里，函数可能保持不交易。目标非零，实际持仓仍可能为零。
反过来，如果目标明确变成 0，该实现会要求清仓。不能假设旧仓位总能被缓冲保护着继续持有。这是信号门槛附近反复进出容易增加交易的一个原因。
**5 缓冲宽度有成本与信号之间的取舍**
缓冲较窄，实际持仓更接近目标，但订单较多。缓冲较宽，订单减少，但实际持仓偏离信号更远，小目标甚至一直无法建立。

**6 信号门槛先决定是否允许分配仓位**
`signal_threshold` 检查的是股票汇总后的 `abs(mean_zscore)`。例如门槛为 0.5，平均偏离的绝对值达到 0.5 才满足进入条件。它没有直接检查某一条配对的 z-score，也没有直接检查最后的权重。
如果进入和退出都用同一条线，信号在 −0.49、−0.51、−0.48、−0.52 之间晃动，就可能反复要求清仓与进入。实际是否成交还取决于缓冲和目标规模。
**7 进入与退出使用不同门槛可以减少来回切换**
Notebook 支持进入门槛 0.5、退出门槛 0.25 这样的设置。这叫 hysteresis，可以理解为给进入和退出留出不同的门槛。

表中描述的是信号资格状态，不能直接等同于券商实际已经成交的仓位。代码随后还会重新计算权重并经过交易缓冲。
在代码的设计说明中，股票离开候选集合会重置这种状态。该机制按信号判断，不能替代亏损限制或事件风险控制。
较低的退出门槛让仓位保留更久，减少进出切换的同时，也可能继续持有预测能力已经减弱的股票。应联合比较换手、成本、持仓数量与收益，而不是只看 Sharpe。
**8 交易缓冲与不同进出场门槛作用在不同步骤**
```plain text
信号门槛与状态规则
    ↓ 决定哪些股票允许有目标仓位
权重计算
    ↓ 决定目标比例
交易缓冲
    ↓ 决定当前实际持仓是否需要向目标调整
模拟或真实成交
```
改变进出场门槛以后，缓冲实验的结果也可能改变。因此，不宜在没有信号门槛的配置里选好缓冲，再直接认定它适合其他配置。
**9 财报过滤试图区分暂时偏离与价值重估**
假设 C 股价上涨，模型认为它偏贵，原本想做空。但 C 刚公布盈利，明显超过市场预期。上涨可能反映新的盈利信息，继续按旧关系做空有风险。
Notebook 的可选规则检查最近一次盈利意外：如果实际每股收益高于预期，且距离对应事件没有超过设定的交易日窗口，则跳过这只股票的空头。它只处理这一类空头情形，没有对所有重大新闻提供保护。
代码把盘前、盘中事件与盘后事件分到相应交易日，财报过滤窗口使用交易日编号，而非简单的日历天数。真正复现还要检查原始数据的发布时间与修订历史。
更重要的是，它会把剩余空头放大，尝试维持原来的空头总规模。例如原本做空 C 20%、D 15%、E 5%，合计 40%。过滤 C 后，D 和 E 剩余合计 20%，各乘以 2，就变成 D 30%、E 10%。
因此，避开一只股票的事件风险，可能把更多风险集中到其他股票。单股上限与最终实际权重需要一起检查。
**10 借券和成交条件也属于策略实现**
做空需要可借股票，还要考虑借券费用、保证金和分红补偿。卖空股票上涨会造成亏损，潜在损失没有固定上限。[SEC 做空说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-51)
回测给某只股票填了借券费率，并没有证明当时一定能借到足够数量。实际执行需要把可借性、额度、费用和最终仓位一起处理，不能只计算一个价格信号。
**11 信息必须先出现，订单才能随后成交**
策略文档描述两条路径：使用收盘前可获得的信号，在收盘前后相应执行；或者取得日终信号后，在下一个交易日执行。文档指出，等待到次日收盘可能损失较多信号优势。
假设使用今天完整收盘数据计算出信号，却在回测中按今天准确收盘价买入，现实中难以严格实现。收盘前的信号又与最终收盘信号不完全相同。公平的模拟需要让信号时间、提交订单时间和成交价格彼此一致。
这比简单地把整张目标表滞后一天更细致：使用次日开盘执行，就应匹配次日开盘的可成交价格、跳空和成本；使用收盘前执行，就应匹配当时真正可获得的信号。
**12 一次日常调仓的完整流程**
1. 读取当前真实持仓、现金和策略净资产，确认数据时间。
2. 取得在决策时已经可用的新信号。
3. 按深度、质量、一致性和进出场规则生成目标。
4. 处理财报、公司行动、借券与仓位限制。
5. 按最新价格计算实际仓位，与目标比较并应用缓冲。
6. 生成需要买卖的差额，核对金额、股数和保证金。
7. 执行后读取真实成交和未成交数量，更新实际持仓。
8. 保存当天的信号、目标、订单、成交、成本和异常原因。
最后一步让以后能够区分：亏损来自信号本身，还是来自数据、成交与持仓记录的偏差。
## 小结
- 价格与净资产变化会导致仓位漂移。
- 交易缓冲容忍小偏差，以较少交易换取对目标较低的贴合度。
- 信号门槛、不同进出场阈值与交易缓冲分别作用在不同步骤。
- 财报过滤和借券约束会改变最终组合，可能提高剩余持仓集中度。
- 回测必须保持信息产生与成交的时间顺序，并锁定实际使用的函数版本。
